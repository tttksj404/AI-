# 경험 기록: Sentinel-30 (AI 해커톤 보이스피싱 공동 대응)

- 계열: `AI-`(대표), `voicefishing`(후속 로컬 시뮬레이터. 포인터만 있음)
- 기간: 2026-05 ~ 2026-05(기획·발표 산출물, 커밋 2026-05-12~05-29, 본인 서술 기간 2026-05-01~05-31) / 후속 음성 파이프라인 슬라이스 2026-08-11 / 로컬 시뮬레이터 2026-08~10
- 인원·구성: 기획서상 6인(기획·발표 1, ML/봇 2, 백엔드 1, UX 1, 법리·보안 1). 레포 커밋 작성자는 3명 이상. 실제 편성은 미확인
- 본인 역할: 레포 커밋 기준 기획 산출물(기획서·발표자료·이미지 생성 스크립트) 갱신, 평가 패키지(`security_layer_eval`)와 음성 파이프라인 슬라이스 추가. 팀 내 공식 직함은 미확인
- 성격: 해커톤(AI 민생 과제 ⑧ 보이스피싱 공동 대응) 팀 기획 프로젝트 + 이후 개인 확장. 운영 서비스 아님, 실사용자 없음
- 최종 갱신: 2026-11-23

## 1. 상황과 판돈
- 무엇 때문에 시작했나: 해커톤 주제 ⑧ 「AI 기반 보이스피싱 공동 대응」. 탐지·차단만 하는 기존 방어와 달리 사기범의 시간·정보·도구를 소모시키는 능동방어 개념(Sentinel-30)을 기획서로 설계(`기획서_Sentinel30_lean.md`).
- 왜 중요했나: 예선 평가항목(문제 적합성 25, AI 기술 활용 30, 파급력 25, 혁신성 20)에 맞춘 기획서와 발표가 심사 대상이었다. 예선 4주 + 본선 무박 2일 구성(기획서 1.2). 심사 결과는 미확인.
- 그때의 제약: 법령 리스크(AI 기본법, 전자금융감독규정 등) 검토 필요, 실제 통신망·금융기관 연동 불가, 실제 음성 복제 금지.

## 3. 판단
- 정한 것: 모든 주장을 `docs/CLAIM_STATUS.md`의 상태(`검증됨`/`부분 검증`/`설계 목표`/`차단됨`/`범위 외`)로 구분해 표기. 원격 GPU 실측은 합성 샘플 한정으로 해석 범위를 제한.
- 정한 사람: 레포 문서로는 본인(작성자). 팀 합의 여부 미확인.
- 버린 선택지: 실제 사용자 음성 복제(정책상 harness가 거부), 실제 통화 연결·call forwarding, 별도 VPN 포털 로그인(JupyterHub 직접 접근이 가능해 불필요 판단). Qwen3-8B는 실시간 기본 모델이 아니라 오프라인 judge 후보로만 둠.
- 판단 근거: 원격 venv가 `torch 2.13.0+cu130`로 설치되어 드라이버(CUDA 12.8)와 맞지 않아, `2.11.0+cu128`로 맞춘 뒤 실제 CUDA 연산을 통과시켰다(`docs/REMOTE_GPU_MEASUREMENTS.md`).

## 4. 결과와 상대의 변화
- 확인된 결과: 합성 transcript 기반 로컬 파이프라인(harness→graph→loop)과 pytest 22개 통과(CLAIM_STATUS 기재, 직접 재실행은 이 기록 작성 중 하지 않음).
- 수치(원격 L40S, 합성 고정 샘플, 2026-08-11): STT 문자 오류율 0.0(1문장) · warm 중앙 223.5ms / Qwen3-4B 48토큰 1,436.6ms, warm 중앙 678.4ms / Qwen3-TTS 7.2초 음성 8,713.2ms, RTF 1.21 / warm-turn 전체 오디오 준비 중앙 11,483.0ms / QLoRA 2 step loss 7.039534→5.896524. 일반 WER·MOS·탐지율로 확대 불가.
- 상대의 변화: 해당 없음(확인된 외부 사용자·심사 반응 없음).
- 안 된 것·남은 문제: vLLM 서버 경로, Extractor JSON 계약, holdout 평가, 스트리밍 TTS 지연, p95는 미측정. TTS 지연이 길어 실시간 통화 용도로는 미달.
